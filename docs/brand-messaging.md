# Metron Brand Messaging

## Brand core

**Metron** comes from Greek *μέτρον* — a measure, standard, or measured unit.

It is the right name because Metron turns each API request into a clear economic unit:

> **One call. One price. One settlement.**

### Brand idea

> **Every useful call deserves a clear price.**

### Product principle

> **Show the transaction. Then execute the work.**

## Strategic diagnosis

Metron is not primarily an API marketplace, a Stripe clone, a crypto wallet, or an AI-agent framework.

> **Metron is zero-code pay-per-request infrastructure for callable APIs.**

It lets a developer publish an existing endpoint as a paid service and lets a human caller or AI agent authorise exactly the request they need.

### Strategic enemy

For creators:

> Billing infrastructure that is heavier than the API business itself.

For agents and callers:

> Human checkout imposed on machine-to-machine work.

## Audience

### Primary launch wedge

**AI-agent developers and indie API creators** who need to publish and consume paid APIs without building billing infrastructure.

### Secondary audiences

- data providers selling query-level access;
- developers in markets with limited card-processor access;
- human developers consuming paid APIs;
- AI agents that need machine-readable payment requirements.

## Positioning

### Category

> **Pay-per-request API infrastructure**

### Positioning statement

> For developers who have useful APIs but do not want to build billing infrastructure, Metron is pay-per-request API infrastructure that turns an existing endpoint into a paid service in minutes. Unlike Stripe integrations, API marketplaces, or x402 frameworks, Metron combines zero-code publishing with Celo-native micropayment settlement for human callers and autonomous agents.

### Primary promise

> **Publish a paid API in minutes, then let callers and agents pay per request on Celo.**

### Difference

- zero-code endpoint monetisation;
- stablecoin micropayments;
- Celo-native x402 settlement;
- agent-compatible HTTP payment;
- creator-side wallet settlement;
- payment-before-proxy execution;
- programmatic failure handling.

### Reason to believe

A live paid call:

```text
API published
→ payment requirement returned
→ agent authorises stablecoin payment
→ Celo settlement confirmed
→ API request forwarded
→ response returned
→ creator receipt generated
```

**Message:** You built the capability. Metron handles the payment layer.

**Proof points:**
- connect a wallet;
- paste an endpoint;
- set a per-request policy;
- receive a powered route.

**Message:** A caller can inspect the price, authorise the payment and receive the response without card checkout or subscription setup.

**Proof points:**
- HTTP 402 payment requirement;
- stablecoin authorisation;
- machine-readable status;

**Message:** Metron shows the route, price, network, settlement state and response instead of asking users to trust an invisible system.

- Call Line;
- Metron Receipt;
- Celo transaction evidence;

**Message:** When a service is useful for one request, the payment should work for one request.

**Proof points:**
- per-request stablecoin pricing;
- Celo settlement;
- no forced monthly plan for a one-off need;
- creator wallet receipt.

## Verbal identity

### Voice

Metron is:

- precise, not cold;
- technically fluent, not jargon-heavy;
- confident, not speculative;
- transparent, not over-explanatory;
- economically literate, not finance-theatre;
- practical, not futuristic for its own sake.

### Voice rules

| Principle | Sounds like | Not like |
|---|---|---|
| Name the transaction | “This call costs 0.005 USDC on Celo.” | “Unlock next-generation value.” |
| Show the working | “Payment settled. API response: 200 OK.” | “The protocol handled everything magically.” |
| Respect the creator | “Monetise the capability you already built.” | “Turn your side project into passive income.” |
| Respect the agent | “The endpoint returned a payment requirement.” | “Your AI can now experience financial freedom.” |
| Be clear about conditions | “No charge if the upstream request fails.” | “Automatic refunds, guaranteed.” |

### Vocabulary

Use:

> **call, route, request, response, price, settle, verify, paid, creator, caller, capability, endpoint, receipt, Celo, stablecoin, policy, evidence.**

Avoid:

> **ATM, jackpot, yield, moon, alpha, magic, seamless, revolutionising, Web3 superpowers, passive income, limitless, AI economy platform, frictionless.**

## The Call Receipt language

The product’s repeated visual and verbal sequence is:

```text
CALLER → ROUTE → PRICE → SETTLED → RESPONSE
```

Example:

```text
METRON CALL / 004821
ROUTE       / translate.v1
PRICE       / 0.005 USDC
NETWORK     / CELO
STATUS      / SETTLED
RESPONSE    / 200 OK
CREATOR     / 0x7A…91C
TX          / 0x84…E10
```

This is a product proof format, not merely campaign copy.

## Hackathon narrative

### Primary track

Metron is most naturally aligned with **Most x402 Payments** because its core loop generates repeated pay-per-request settlements through Celo’s x402 facilitator.

### Secondary track

It can also pursue **Most Revenue Generated** through the required Celo attribution and transaction-tagging flow where applicable.

### Demo story

1. A developer connects a wallet.
2. They paste a translation or data API endpoint.
3. They set a price of `0.005 USDC` per call.
4. Metron publishes a powered route.
5. An agent calls the route.
6. The agent receives and authorises the payment requirement.
7. The Celo transaction settles.
8. Metron forwards the request.
9. The API returns `200 OK`.
10. The creator sees the receipt and wallet settlement.

### Closing line

> **An agent paid a developer for a real API call on Celo.**

## Claim boundaries

- Do not claim “instant” or “automatic refunds” without showing the implemented settlement behaviour.
- Do not imply that every country has identical regulatory, payout or wallet access conditions.
- Do not call Metron the “only” product combining these capabilities until competitive research confirms it.
- Do not claim a specific transaction fee, finality time, user count or market size without a current source.
- Celo should be presented as infrastructure that enables the flow, not as decorative brand language.

## Final recommendation

Metron should be remembered as:

> **The clear payment layer for API calls.**

The product should always bring the user back to one proof:

> **One call. One price. One settlement.**
